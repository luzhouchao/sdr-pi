# IIO refill 长度合同与故障注入

基线bb8b512。只读P201映射确认现有daemon加载`/usr/lib/libiio.so.0.21`。
上游v0.21的buffer.c把非负refill返回值保存为data_length，buffer_end取该有效
长度，而不是固定容量。原假设“正常短读必然写入旧尾部”不成立；仍需验证
异常API返回与跨度不一致时的失败关闭行为，不把防御性修改称为RF根因修复。

本单元范围：统一现有raw采集和兼容power路径的refill检查，要求有效返回值、
跨度与已配置整缓冲字节数一致，且完整ci16对齐。拒绝零、短、超长、不对齐、
空/逆序指针或返回/跨度不一致；不消费坏块。最终请求少于一个完整缓冲的尾段
仍从合法整缓冲截取，不误当短refill。底层负errno保留。

直接在测试中替换现有Adapter的libiio函数指针；不增加生产注入开关、不操作
真实硬件。覆盖成功多refill与请求尾段、首次/后续坏refill、短/零/超长/不一致、
负超时/溢出/取消、raw失败文件/目录清理与capture_active释放，以及兼容power
路径拒绝输出。先运行旧实现捕获负例，再修复。运行已有sdrd测试和新测试，
使用ASan/UBSan补充检查，并用固定ARMv7技能构建验证ABI；不替换已安装服务。

实机仅只读核对libiio身份/映射与必要反汇编；无新RX/TX、模型、dataset读取。
临时文件只在`/var/tmp/sdrharness-dev/iio-refill-907r/`，外部上游源码和目标库
如需临时读取，登记URL/路径、hash、字节数，完成后与构建/测试数据一并清理。
保留有界结果和哈希，不增加IQ副本。源码合同/故障测试完成与目标采集实测分列，
部署和实收修复未完成就不勾选。生产识别不可用、旧门与RF-v1保持。
