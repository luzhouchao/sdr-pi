## 尽早启动、按条件插入的工作

- **V1b：独立 known-RF/OOD 标签与覆盖证据。** V1a 完成后即可由用户或独立
  来源准备/审核。记录已知类、噪声/空闲、类外及混合/低质量情况，保留来源、
  session/day、谱域条件和歧义。Agent 可以做校验工具，不能把模型预测变成标签。
  工具可用、拿到少量样本、覆盖达标是三个不同状态。
- **V3a：数字 ID/文本名称映射证据。** 可在 V1a 时开始核对；在独立标签进入
  校准前，应确认数字 ID 的含义和对应依据。证据不足时继续使用可信数字 ID，
  文本保持 provisional，不因界面需要显示名称就宣布争议已解决。
- **V2 可前移。** 如果 V1b、V3a 和 S2 校准读取合同提前具备，V2 可插入任一
  已完成交付之后，无需等 UI 或长时测试。V3b 仍只能在规则冻结后开展；A1 仍须
  等所有软件、资源和数据准入门齐备。
- **S6a 可与 S3/S4a 调换。** 若模型环境或 GPU 验证窗口暂不可用，S2 完成后可
  先做存储/UI；不要为等待硬件而停止有价值的软件工作。完整 S6 不提前勾选。
- **故障/fuzz 随修改覆盖。** S2/S3/S5 各自补本接口负例，不把所有故障验证拖到
  O1a；O1a 的目标是统一可重复验证和运维交付，不机械重跑已冻结模型实验。

这是任务依赖安排，不要求多 Agent 并行。若 V1b 仍缺数据，继续完成可独立推进的
软件单元；到 V2/V3b/A1 时明确记录缺失证据，不伪造数据、不通过改配置绕过。

## 每次新任务的执行规则

1. 先读 `AGENTS.md`、权威 checklist、本文件和拟修改子系统的相关文档。
2. 核对分支/HEAD/工作区，从本表选择依赖已满足且尚未完成的**一个独立交付**。
   S1/S2/V1a/S3/S4a/S6a/S5/S6b/S4b/O1a 已完成；下一步核验 V1b/V3a 证据，
   V2 仅在前置条件满足后开展，不重做已完成单元。
3. 小单元完成条件需写清；S4a 不代表 S4b 完成，S6a 不代表 S6b 完成，V1a 不
   代表 V1b 有了独立标签。清单保留这些区分。
4. 测试、适用的实机验证、精确临时数据清理、checklist 更新和 diff review 均
   完成后，创建聚焦提交并立即 push。只做文档规划无需创建采集临时目录。
5. 始终沿用冻结 epoch-10/FP16/RF-v1；不重跑完整精度实验、不自行训练、不用
   locked test 调试。生产架构固定 P201 RX1/RX0/A_BALANCED → AGX；无 TX、
   FPGA/BOOT 或 NX offload。第7章设备/辐射源身份识别不加入当前关键路径。
