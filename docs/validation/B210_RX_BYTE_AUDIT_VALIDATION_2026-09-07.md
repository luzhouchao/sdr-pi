基线 `1ff065d`，按[方法登记](../evidence/B210_RX_BYTE_AUDIT_PLAN_2026-09-07.md)执行。

## 结果

原2455 MHz包67个文件的路径、大小、SHA-256及原生报告/RX身份全部验证。
分析15份采集（tone与四个RML组，各有baseline/during/after），共983,025个
复样本、3,932,100字节，覆盖每份65535点，包括末尾不完整分析块。
完整数值、来源身份、只读设备输出和源码哈希见
[审计](../evidence/B210_RX_BYTE_AUDIT_2026-09-07.json)。

- Python struct与NumPy的小端I/Q解码逐值相同；全部1,966,050个分量符合
  有符号12位扩展。若强行按大端解释，有566,532个分量超出12位范围。
  当前实机RX scan格式为`le:S12/16>>0`、voltage0/1索引0/1，支持现有解码。
- 7,665个完整128点对齐块、225个完整4096点对齐块，均未发现同一采集内或跨采集
  的精确重复。最长全零串和同值串均仅6点；没有整段补零的迹象。这不检查
  任意错位长度的重复，也不排除替换成其他合法样本的错误。
- 每份15个4096点边界均计算相邻样本跳变、全长差分百分位及两侧128点RMS。
  每份最大的10个相邻128点功率变化共150项，仅1项落在4096边界；三个失败
  during组的最大变化见下表。这个后验计数没有显著性或因果判定含义。

| 失败组during | 最大128点功率变化的起点 | 对4096取余 | 所有缓冲边界中最高跳变百分位 |
| --- | ---: | ---: | ---: |
| high1 | 31488 | 2816 | 97.262% |
| high2 | 54016 | 768 | 94.313% |
| low2 | 38912 | 2048 | 95.387% |

因此，本包没有支持“简单端序错误、整块重复拷贝、成片补零或固定缓冲边界
拼接突变”的证据。**不能据此证明没有掉样，也不能排除模拟链路或DMA内部问题。**
未知污染与原坏窗仍存在；不把本次检查通过当成旧RF/分类门通过。

## 软件路径和证据局限

`sdrd_iio.c:adapter_capture_iq`检查scan样本大小为4字节，直接把IIO缓冲字节写入
临时文件；`sdrd.c:append_base64_file`核对文件长度并编码，AGX `SdrdWire`按有界
完整行和request ID收取响应，`sweep.rs:decode_base64/SigmfWriter::append`解码并
原样写入SigMF，分析使用`i16::from_le_bytes`。这条路径没有软件拼接四个模型窗
后再反写原IQ的过程；窗口分析发生在完整采集之后。

但以下保证目前不能从记录推导出来：

1. `sequence`是采集调用序号，不是ADC逐样本计数；`dropped_samples`统计接口
   短缓冲，`overflow`依赖底层返回错误。全为0不等于已独立验证连续性。
2. 当前原始采集路径检查refill负返回值，但写入长度取`buffer_end-start`，没有
   显式拒绝正返回长度与该跨度不一致的情况。需要单独核查实际libiio语义并
   做短refill故障注入；本轮没有出现已证实的不一致，不冒充找到了根因。
3. 原生响应没有独立P201端payload哈希。现有AGX哈希证明封存后内容未改变，
   不能单独证明封存前全链路没有错误。合法范围也不是校验码：测试明确包括
   一种字节交换后仍在12位范围内的反例。

源码审计绑定当前文件哈希；没有重新构建来宣称当前源码与已安装二进制逐字对应。
保留数据的身份/参数仍以原封存采集报告为准，当前只读sysfs不是历史采集快照。
